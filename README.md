## 01 / WORK

### VREALM

A long-term R&D project around generating complete 3D environments from natural language inside **Unreal Engine**.

The project is split into several layers for language understanding, scene representation, constraints, composition, execution and evaluation.

The main goal is to keep the whole generation process structured and inspectable instead of relying on one large opaque generation step.

**Main areas:** Unreal Engine, C++, semantic systems, procedural generation, machine learning.

Currently working on:

- semantic extraction
- scene graphs
- deterministic scene generation
- constraint handling
- procedural environments
- Unreal execution systems

`ACTIVE R&D`

### WORKSHOP

A desktop application for configuring Minecraft plugins (tailored specifically for my own plugins) without having to work directly inside large YAML files all the time.

The configuration files stay complete and portable, while Workshop adds proper tools around them.

**Built with:** TypeScript, React and Electron.

Current and planned features include:

- YAML and JSON editing
- schema validation
- tree and focused views
- configuration search
- import and export
- diff and merge tools
- plugin-specific editors
- previews where useful

`IN DEVELOPMENT`

## 02 / WHAT I LIKE

### Game systems

I like building mechanics that can interact with each other instead of isolated features.

Minecraft plugins are a large part of that work, especially systems that are configurable enough to be reused in different ways.

I currently work mostly with **Java, Paper and Maven** for that side of things.

<br>

### Developer tools

I often end up building tools around the projects I work on.

That can mean configuration software, validation tools, scripts, repository utilities, automation or small programs that remove repetitive work.

Python and Bash are usually involved somewhere.

<br>

### 3D and game art

I enjoy the visual side of game development just as much as the software side.

Modelling, texturing and animation give me a very different kind of problem to solve compared with programming.

I particularly like:

- stylized assets
- low-poly modelling
- pixel-art textures
- strong silhouettes
- fantasy designs
- game UI
- unusual interface design

<br>

### AI and automation

I'm interested in AI mostly as an engineering tool.

Things like:

- information extraction
- small specialized models
- fine-tuning
- agent workflows
- structured generation
- automated development tools
- reducing unnecessary model usage

I prefer using models as one component of a larger system rather than building everything around a model.

<br>

### Games and interfaces

A lot of my design references come from games rather than modern web applications.

I like interfaces that have their own visual language and still remain practical to use.

That applies to games, desktop software and developer tools.
